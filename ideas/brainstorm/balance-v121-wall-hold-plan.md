# SIM_VERSION 121: Hard AI melee wall hold uses per-hero drawn width (plan from 5 narrow planners, 2026-11-27)

Source finding: `ideas/brainstorm/melee-wall-hold-drawn-overlap.md`. Plan notes (stubs): `~/claudetmp/plans/v121-1-rule.md` .. `v121-5-measure.md`, widths script `~/claudetmp/plans/v121-2-scan.py` (copy into `tools/` if kept). Built AFTER the held v120 (`balance-v120-plan.md`) is merged and re-recorded; one sim-changing agent at a time.

## Decision: option (a), a per-hero integer table in core data
- Rule today (`src/core/agents/scripted-ai/arcade-ai.ts:493-515` `wallHold`, caller `arcade.ts:448-455` `wallHoldStep`): Hard AI only (`level >= AI_HARD`), fight phase only; with a pinned foe, `gap` = x distance between the two SIM boxes; melee `hold` = `ARCADE_AI_WALL_HOLD_MELEE_PX` 32 (0.4 of an 80 px body), ranged 144, near 48, slack 16; `gap < hold - 16` and room = away bit, `gap <= hold` drops the toward bit. Units: sim px, boxes only.
- The overlap comes from art wider than the box (the view draws at `arcadeHeroScale` k up to 2). Measured idle overhang per side (MEASUREMENT, opaque alpha >= 32 over the widest idle frame, `v121-2-scan.py`): curomo 40/35, pax 39/38, treenoc 38/35, echo 40/39, wispera 34/25, kindrel 38/37, nykra 37/37, brazgor 34/32, durrok 44/45, ouroth 69/69 (box 200x90), abyssor 20/21, vortigal 39/41; worst frames (attack/dash/ko) add 10-15 px per side (ouroth up to 100). Every melee hero is over 8 px per side, so none is exempt; a single constant is wrong.
- Design: `CHARACTER_DRAWN_EXTRA_PX` (integer px per side, default 0) in `src/core/data/size.ts` (or `arcade-numbers.ts`); `wallHold(self, opp, cmd, pf, ranged, extra = 0)` adds `extra` to the MELEE hold only (extra = the sum of the two heroes' overhangs toward each other, possibly scaled by a fraction chosen after measuring; do not size from idle alone, but do not use the full worst frame either); `arcade.ts` `wallHoldStep` passes it from the two heroes' slugs (find the character id source in the state first). Default 0 keeps the existing unit tests green.
- Layering: core never imports the view. A `tests/repo` test imports the core table and the view's measured half-widths (PNG decode via `tools/assets/png-lite.ts` + the `OPAQUE_ALPHA_MIN` rule of `opaque-span.ts`) and asserts every melee hero has a row >= a fraction of its measured idle overhang; a new hero without a row fails.
- Rejected: (b) scale by sim box width (the overhang is not proportional: ouroth 200 px box vs kindrel 80 px; hyalia is tall, not wide); (c) view-only clamp (the drawn position no longer matches the hit box).
