# Parity checklist (legacy Crafty.js vs Phaser/TypeScript port)

Seed: plan section 4.2. Every row maps one legacy behaviour to its new behaviour and a status:

- **matches**: the new code behaves like legacy, proven by at least one named, passing, non-`it.fails` test. A legacy
  bug that is reproduced on purpose also counts as a match; its row names the slug and the pending fix.
- **intentional divergence**: the new behaviour differs from legacy on purpose; the evidence proves the new behaviour.
- **open**: not proven yet (no test, partial test, or manual sign-off still to do). Nothing is fixed by this document.

Evidence cells hold `path#test title (or a unique part of it)`. `tests/repo/parity.test.ts` checks that every
reference exists in the named file, that a `matches` row cites at least one test, and that no `matches` row relies on an
`it.fails`. The cited tests run in the normal `pnpm test` / `pnpm test:legacy` suites. "manual" means the WP 96
sign-off playtest. Bug slugs are those of [docs/legacy/KNOWN-BUGS.md](legacy/KNOWN-BUGS.md) plus the port-found ones
(tagged `KNOWN-BUG:<slug>` in `src/core`), which are listed there too.
